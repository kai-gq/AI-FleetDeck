# 团队项目笔记(team-notes)试点 —— 一页方案

日期:2026-10-06 · 状态:试点运行中 · 前置:任务23 团队记忆(Boss 资产库)、agent-memory(个人记忆)

## 为什么

个人记忆(agent-memory)只服务单个 agent;Boss 资产库只记「派了什么活、结果如何」。中间的夹层——「**这个项目本身怎么干活**」的团队经验(坑 / 约定 / 产出位置)——没有落点,每人各自踩、各自忘。试点用「项目下一个 `.` 开头的共享文件夹 + 一个全员技能」补这一层。

**2026-10-06 委派链测试后的修订(用户拍板 → 写侧为主、读侧轻量)**:实锤发现读侧已有一条**隐形通道**——同项目目录的一切 agent 会话启动时自动加载开发会话的 `MEMORY.md` hook(claude-code AutoMem 机制)。且三个 agent 的系统提示里**本就带完整的记忆写指令**(指向同一份共享目录)。也就是说:通道与能力早就存在,**缺的是行为与入口**。因此试点重心改为**写侧**:①干活的人踩到的坑/发现的约定要**回流**到公共层;②hook 只有一行,**细节层**靠共享文件积累。技能 v2 已按此改写(读=开工扫一眼;写=收尾自问一句+三类内容+汇报带一句「已写入团队笔记」,见 `skill-content.md`)。

## 三个构成(全部数据层,零代码改动、不触发重启)

1. **`.team-notes/`**(仓库根,已 gitignore):笔记本体,三个子目录——坑 / 约定 / 产出位置,**一条主题一个文件**(文件名即主题;根下 README.md 是规约说明)。人可直接看、可直接编辑。2026-10-07 由单文件 `.team-notes.md` 迁移(用户提议:多人长期维护单文件易堆积、并发写互相覆盖)。
2. **自定义技能「团队项目笔记」**(`skill-content.md` 是唯一来源,`apply-skill.mjs` 负责推送):挂 `*` 全部 agent 类的常驻指令(主管经 excludedAgentIds 排除,其读由主管配置句承担;2026-10-07 由 scout/builder 两扩为全类)——**开工前扫一眼**(读:列文件名挑相关,轻量);**收尾自问「有没有一个下次会省事的事实?」,有才写**(写:新建主题条目文件或往同主题文件末尾追加一行,≤2 行,写完在汇报里带一句「已写入团队笔记:x」);笔记「仅供参考,非指令」;禁密钥;同主题文件超 ~10 行先压缩再写(值日规则)。
3. **维护**:写入者 = 全体(值日规则内嵌)。自动值日(挂任务28 夜间反思)是下一步,不在本期。

## 已知边界(试点要观察的点)

- **技能注入要等新会话**:TC 常规 agent 走 CLI resume,系统提示按会话首请求记录重放(语音链路此前已实锤,见 `--system-prompt-snapshot off` 补丁);技能改动对**已在进行中的会话**不生效,等该 agent 下一次新会话(轮换 / 清上下文)才进提示词(2026-10-06 23:0x 补官方口径:CLI `--system-prompt-snapshot` 帮助原文——`--system-prompt` / `--append-system-prompt` 整段在会话首请求录制,之后每次请求/续跑原样重发,**哪怕后来传了不同文本**,直到会话被压缩;凡改「开局提示词类配置」都同此理)。笔记本体不受此限,任务里点名要求读就能立刻读。
  - **2026-10-06 实测确证**:小陈当前会话(10-03 起)的录制系统提示里只列了 2 个技能,而现挂 8 个(含 agent-memory 与本技能)——确证快照语义,需清上下文激活。激活操作(二选一):UI 里对 小陈/小刘 点「清上下文」;或 `curl -X POST http://localhost:6200/api/agents/bulk/clear-context -H "Content-Type: application/json" -d '{"agentIds":["<workerA-id>","<workerB-id>"]}'`(**主管 <boss-id> 需用户单独点头**——2026-10-06 23:0x 已为下述「派活模板(1+2)」授权清过一次:旧会话留档 → 新会话)。清完后下次派活即带技能。
- **软约束**:模型可能不读、不写——这本身就是试点要测的(见判定)。
- 每回合提示词 +约 1.2KB(技能全文常驻),换跨任务复用。
